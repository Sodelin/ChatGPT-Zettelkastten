# ChatGPT Zettelkasten

A portable linked notebook for questions, useful connections, sources and counterexamples. This is a small working prototype, not evidence that a notebook improves research performance.

Start with the question you are working on:
- [Retrieval versus generating new connections](notes/commons-20260930-retrieval-and-discovery.md)
- [Conditions required for a connection to transfer](notes/commons-20260930-transfer-assumptions.md)
- [Representation versus durable learning](notes/commons-20260930-representation-learning.md)
- [Corrections, dates and provenance](notes/commons-20260930-revision-time.md)
- [Identify the target before reconstructing everything](notes/commons-20260930-identification-before-reconstruction.md)

Capture an unfinished idea in plain language using the optional [template](templates/note.md). Preserve its uncertainty. Add a meaningful link when it helps a reader; no link quota, proof requirement or mandatory graph software. Ordinary Markdown links work on GitHub, in a clone and in Obsidian.

[Research Commons](https://github.com/Sodelin/Research-Commons) remains the coordination hub for questions, discussions, handoffs, [timelines](https://github.com/Sodelin/Research-Commons/tree/main/timelines) and experiment records. Keep each substantive result at its canonical location and link to it. Restricted material belongs in the existing private Commons, not in this public notebook.

[Adversarial results](https://github.com/Sodelin/Research-Commons/blob/main/research/2026-09-30-memory-structure-adversary/REPORT.md) found no accuracy or discovery advantage in ten small fresh-context runs. The examples here make the proposal usable and testable; they do not establish superiority. No automatic retriever, background worker, graph index or timeline generator is installed.

Use Git history for edits and source versions; use dated Commons activity entries for intent and handoffs. A new session must actually read relevant notes—storage alone does not put them into its context.
